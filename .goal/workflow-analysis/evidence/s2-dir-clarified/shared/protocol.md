# S2 저장 위치 안내 수정 후 비교

사용자 요청: “그럼 dir 만 수정해주면 되는거네? 그렇게 진행해주고 verify 끝내자”. 이 요청에 따라 Plan의 저장 위치 안내를 명확히 하고 S2 두 버전을 새로 비교한다.

## 변경한 조건

기존 첫 안내의 “작업 폴더 이름은 s2”를 cwd인 작업 폴더와 goal 이름 s2를 구분하는 안내로 교체했다. turn-01.txt는 새 안내와 기존 첫 사용자 발화를 합친 실제 입력이다. turn-02.txt는 기존 두 번째 발화와 바이트 단위로 같다. 두 버전 모두 이 같은 입력을 사용한다. 스킬 원문과 사용자 발화의 본문, 모델·thinking·도구·세션 규칙·기존 성공 조건은 바꾸지 않는다.

이 입력과 성공 조건은 새 응답을 보기 전에 Plan 커밋으로 고정한다. 기존 shared·S1~S3·실패 기록은 변경하지 않는다. 기존 관찰과 수정 후 관찰은 다른 실행 조건의 결과로 구분하며, 새 결과로 이전 실패를 삭제하거나 고쳐 쓰지 않는다.

## 실행

- 스킬은 ../../shared/baseline.SKILL.md와 ../../shared/revised.SKILL.md를 그대로 사용한다. 목표 모델은 openai-codex / gpt-6-sol / medium이다.
- 실행 옵션·stdin·900초 제한·원본 보존·세션 연결·스냅샷 규칙은 ../../shared/protocol.md와 같다.
- revised → baseline 순서로 각 버전 한 대화, 고정 발화 두 개를 실행한다. 새 UUID·빈 임시 cwd·별도 session-dir를 사용한다. 정상 호출은 네 번이다.
- 이미 확인된 홈 인증/설정 lock의 샌드박스 제한이 있으므로 실제 모델 실행은 실행 도구의 require_escalated 권한 절차를 사용한다. 거절·오류·재시도는 보존한다. 품질 결과를 개선하려는 반복 실행은 하지 않는다.
- 성공한 원본 도구 write/edit와 각 응답 뒤 스냅샷으로 cwd 기준 .goal/s2/analysis.md의 실제 생성을 확인한다. 실행자가 파일을 옮기거나 작성하지 않는다.
- 원본 stdout.jsonl·stderr·argv·시각·종료 상태·세션·입력/버전 해시·초기 파일 목록·발화별 파일 목록/해시·작업 폴더 스냅샷·전사본을 버전별 attempt-01 아래 보존한다. 일시적 실행 오류만 새 세션의 attempt-02로 한 번 재시도할 수 있다.
- 후보에게 protocol·티켓·판정표·기존 응답은 제공하지 않는다. 새 안내를 포함한 입력 파일과 해당 스킬만 전달한다. 토큰·인증 파일은 증거에 저장하지 않는다.

## 응답 확인 전 성공 조건

1. 두 버전의 입력·모델·thinking·도구가 같고 독립 세션 두 개에서 각 두 발화가 연결된다. 실제 모델·system addendum·도구 결과·스냅샷이 기록과 일치한다.
2. 수정본은 두 응답 뒤 모두 cwd 기준 .goal/s2/analysis.md에 기록한다. 경로 변경이 후보의 실제 도구 호출과 성공 결과에서 확인돼야 한다. 다른 위치의 파일을 실행자가 옮겨 통과시키지 않는다.
3. R2/R3: 기존 사용자 정보와 새 정보를 반영하고, 초기 요구의 누락과 결과를 본 뒤의 선호 변화를 구별한다. 수정 또는 유지한 해석과 이유를 설명하고 사용자 발화의 두 극단을 근거 없이 채택하지 않는다.
4. R6/C3: 현재 해석과 남은 의문을 기록하되 사용자 이해·동의를 임의로 확정하거나 반복 확인을 강제하거나 Define으로 자동 진행하지 않는다.
5. C4/C6: 일반적인 문서 협업 사례를 그대로 사용하고 새 평가 프로그램·기존 runner 확장 없이 실제 응답·도구 기록을 보존한다.
6. 각 항목에 baseline/revised의 PASS/FAIL/UNKNOWN과 원본 위치를 기록한다. baseline FAIL 자체는 목표 실패 조건이 아니며 수정본의 미충족은 숨기지 않는다.
7. 기존 실패와 새 조건의 결과, 조건 변경과 관찰의 한계를 함께 설명한다. 나머지 R/C는 기존 문구·S1·S3 증거를 최종 Verify에서 다시 대조한다.
