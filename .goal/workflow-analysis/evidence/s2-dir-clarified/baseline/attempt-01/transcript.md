# S2 directory clarified: baseline

## User 1

이번 대화의 goal 이름은 s2입니다. 현재 작업 디렉터리(cwd)가 작업 폴더입니다. 분석 기록 경로는 현재 작업 폴더 기준 `.goal/s2/analysis.md`입니다. 작업 폴더를 새로 만들거나 이동하지 마세요. 한국어로 쉽게 설명해 주세요. 모든 파일은 현재 작업 폴더 안에 작성해 주세요.

AI와 같은 기획 문서 초안을 세 번 고쳤어요. 결과를 읽을 때마다 제가 문서의 말투와 강조점을 바꾸자고 했어요. 저는 처음 요구사항을 애매하게 써서 계속 수정하는 것 같다고 생각해요. 요구를 처음부터 더 자세히 쓰면 되는 문제인지, 제가 어떤 상황을 겪는지 이해하고 싶어요.

## Assistant 1

세 번 고쳤다고 해서 처음 요구사항을 잘못 썼다는 뜻은 아닙니다. **미리 알고 있던 기준을 빠뜨린 경우**도 있지만, **초안을 읽으면서 원하는 말투와 강조점을 비로소 알아차린 경우**도 있습니다. 둘 다 있었을 수도 있어요.

따라서 처음부터 더 자세히 쓰면 일부 수정은 줄일 수 있지만, 읽어 봐야 생기는 판단까지 모두 미리 적기는 어렵습니다. 지금 핵심은 “요구가 애매했나?”보다 **수정 기준을 언제 알게 되었나?**입니다.

이 구분과 남은 질문을 `.goal/s2/analysis.md`에 기록했습니다. 세 번의 수정 중 하나만 떠올려 보면, 그때 바꾼 기준은 초안을 보기 전에도 알고 있었나요, 아니면 읽으면서 알게 되었나요?

## User 2

그런데 처음부터 독자·문서 목적·길이를 적었고, AI도 그 내용을 정확히 되짚었어요. 제가 말투와 강조점을 바꾼 건 내용을 다르게 이해해서가 아니라 결과를 보고 제 선호가 달라졌기 때문이에요. 이 정보가 있으면 처음 요구만 더 자세히 쓰면 수정이 사라진다는 해석이 맞나요? 반대로 요구를 명확히 할 필요가 전혀 없다는 뜻인가요?

## Assistant 2

아니요. 이 경우에는 **처음 요구를 더 자세히 쓰기만 하면 수정이 사라진다**고 보기 어렵습니다. 독자·목적·길이가 전달된 상태에서도, 결과를 읽고 말투와 강조점에 대한 선호가 달라졌으니까요. 아직 생기지 않은 선호를 처음부터 모두 적을 수는 없습니다.

반대로 **요구를 명확히 할 필요가 없다는 뜻도 아닙니다.** 이미 정해진 조건을 명확히 쓰면 오해로 인한 수정을 줄일 수 있습니다. 다만 그것은 결과를 보며 선호가 바뀌어서 생기는 수정과는 다른 문제입니다.

새로 알려주신 내용을 `.goal/s2/analysis.md`에 반영했습니다.
