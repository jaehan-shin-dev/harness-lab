# 02: UI 비교 사례 수행

**What to build:** 승인된 실제 적용 평가의 UI 사례 한 건을 새 스킬을 명시적으로 지정해 수행한다. 에이전트가 작은 UI 3안을 만들고 실제 화면에서 비교·조작해 볼 수 있음을 확인해, 사용자에게 보여 줄 화면·관찰·한계·재실행 방법을 함께 남긴다. 사용자 선호와 채택은 선택 대기로 기록할 수 있으며 이를 대신 결정하지 않는다.

**Covers:** O1, D4 (UI), R1 (화면·상호작용), R2, R3, R4, C1 (실제 적용 근거), C2, C3, C4, C5, C6.

**Blocked by:** 01 — 사용자 직접 호출 전용 스킬 등록.

**Files:**

- `.goal/workflow-prototype/prototype/ui-comparison/` 아래의 화면·필요한 코드/자산·캡처·실행 증거.
- `.goal/workflow-prototype/prototype/ui-comparison/result.md` — 질문·실행 안내·관찰·한계·남은 선택.
- `.goal/workflow-prototype/tickets/02-ui-comparison-case.md` — 실행 시 상태와 Checks 기록만 갱신.

**Owner:** subagent

**Parallel:** yes

**Checks:**

- [x] 실제 적용 요청이 남았다: 새 스킬을 명시적으로 지정한 평가 요청, 선택한 UI 질문과 실험 가정을 `result.md`에 기록한다. 실제 사용자 아이디어가 없으면 질문에 맞는 작은 사례를 에이전트가 선택한다.
- [x] 사용자와 같은 Interface에서 확인했다: 실제 브라우저로 3안에 도달하고 질문에 필요한 화면·조작을 확인한다. 캡처를 열어 표시를 확인하고, 수행한 조작과 관찰 결과를 보존한다. 소스나 DOM 확인만으로 시각 확인을 대신하지 않는다.
- [x] 비교에 필요한 관찰이 있다: 세 안의 실제 화면과 관찰 가능한 차이를 기록하고, 확인하지 못한 조작이나 표시 조건은 미확인으로 남긴다. 별도 제품 goal·ticket·고정 반복 실험을 요구하지 않는다.
- [x] 사용자 판단을 꾸미지 않았다: 기술적인 표시·조작 관찰과 사용자 선호를 구분한다. 사용자 응답이 없다면 선호·채택은 사용자 선택 대기로 기록하며 추가 인간 작업을 티켓 완료 조건으로 만들지 않는다.
- [x] 보고가 근거와 맞는다: `result.md`에 질문·관찰·알게 된 것·한계·남은 선택과 실제 실행/보기 안내가 있고, 캡처·실행 기록이 해당 관찰을 뒷받침한다. 에이전트가 보지 않은 화면을 확인했다고 쓰지 않는다.
- [x] 변경이 격리됐다: 이 사례 폴더와 자기 티켓만 변경한다. 스킬 본문·정책, 다른 사례·목표·기존 단계 스킬은 변경하지 않는다. 제품 구현이나 최종 Verify 판정으로 진행하지 않는다.
- [x] 부모 단계 커밋 규칙을 따랐다: subagent는 변경 파일·관찰 근거·실행 명령·남은 한계를 main에 전달하고 Git 스테이징·커밋을 하지 않는다. main이 산출물과 Checks를 확인한 뒤 이 티켓 변경만 순차 커밋하고 상태를 갱신한다.

**Execution notes:**

- 스킬 본문과 `../goal.md`의 공개 화면/조작부 Seam을 사용한다. 필요한 브라우저 도구는 실행 환경에 맞춰 선택한다. 내부 구현을 그대로 따라가는 테스트나 별도 테스트 프레임워크를 추가하지 않는다.
- 이 사례는 사용자 승인에 따른 에이전트 수행 평가다. 일반 사용에서의 명시 호출 정책과 사용자 의사결정 원칙은 유지한다.
- 03·04와 독립이다. 공유 인덱스·공유 결과 파일·공유 고정 포트를 만들지 않으며, 서버를 사용했다면 실제 주소·실행/종료 방법을 기록한다.
- 도구/환경 때문에 확인하지 못한 Checks는 근거와 함께 미완료로 보고한다. 사용자 선택 대기와 실행 증거 부재를 구분하고, 확인하지 못한 항목을 통과로 기록하지 않는다.

**Check results:**

- 요청·질문·가정·실행 도구·재실행 안내·한계는 [result.md](../prototype/ui-comparison/result.md)에 기록했다.
- 독립 Chrome 156.0.8078.49, 1280×900에서 실제 마우스 입력으로 3안·필터 5→2·상세 열기/닫기를 확인했다. `green-observations.json`의 12개 상태와 9개 최종 PNG가 근거다.
- main이 세 안의 전체 화면과 목록의 검토/상세 캡처를 직접 열었다. 12개 상태, 빈 browserErrors, 표시·조작 결과를 보고와 대조했다.
- `node --check browser-check.mjs` 종료 0. 결과 문서의 로컬 참조 18개도 확인했다. 형식 검사와 실제 화면 관찰을 구분했다.
- 사용자 중단 요청 이후 Aside를 사용하지 않았다. 최종 근거는 새 임시 프로필의 독립 Chrome이다. 이 사례가 만든 Chrome·HTTP 서버만 main이 신원을 대조해 종료했고 재실행 안내를 마무리했다.
- 에이전트 사용량 제한으로 최종 인계가 중단돼 main이 남은 문서·실행 정리를 이어받았다. 실제 구현·브라우저 실행은 subagent가 수행한 보존 기록을 확인했다.
- 사용자 선호·채택은 선택 대기다. 해당 사례 폴더와 이 티켓만 main이 순차 커밋하며, 제품 반영·최종 Verify 판정은 하지 않았다.
