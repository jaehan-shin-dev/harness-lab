# 스킬 가독성·최소성·중복 개선

- 단계: Define 완료. Plan 검토 중 사용자가 ticket 03·D1만 선택한 범위 조정을 반영했다.
- 작업 폴더: `.goal/skill-readability/`.
- 입력: `analysis.md`, 현재 `.agents/skills/`와 `AGENTS.md`.
- 기준 버전: `744310a`의 스킬 원문. 변경 대조에 이 버전을 사용한다.
- 표기: `[합의 Qn]`은 해당 질문의 사용자 결정, `[합의 추가]`는 Round 2 답변에서 추가한 제약이다.

## Objective

- [합의 Q1] 사람이 스킬을 빠르게 읽고 수정하기 쉽게 만든다. 에이전트가 기존 지시를 정확히 실행할 수 있어야 한다.
- [합의 Q4 수정] 현재 상태에서 최소한만 변경한다. 언어 통일보다 기존 문서를 국소적으로 다듬는 것을 우선한다.

## Deliverable

- [합의 Q2] `.agents/skills/`의 SKILL.md 10개와 부속 Markdown 문서 4개가 검토 범위다. 실제 개선이 필요한 파일만 수정한다.
- [합의 Q5 / Plan 범위 조정] `.agents/skills/workflow-define/SKILL.md`의 Evaluation 항목만 D1 수정안대로 나눈다.
  - 기존 제안의 ticket 03 식별자를 유지하며, 적용 대상은 D1 한 건이다.
  - 반복 설명은 강조의 효용이 있다는 사용자 판단에 따라 나머지 스킬과 부속 문서는 그대로 둔다.
  - 템플릿, 용어 정의, 예시·도표의 위치는 유지한다. 새 공통 문서나 파일 이동을 만들지 않는다.
- [합의 Q6] Verify 산출물에 변경별 개선 근거, 기존 고유 지시의 보존 여부, 링크 확인 결과를 기록한다.
- [합의 추가] `.goal/skill-readability/`의 작업 문서에 변경안별 식별자, 대상 파일, 원문, 수정안, 이유, 사용자 승인 여부와 적용 상태를 기록한다.

## Requirements

- R1 [Plan 사용자 결정으로 제외]: 이번에는 중복 설명을 줄이지 않는다. 사용자는 다른 제안의 반복을 강조로 받아들여 원문 유지를 요청했다.
- R2 [합의 Q5 / Plan 범위 조정]: Define의 Evaluation 항목을 구성 정의와 두 조건부 지시로 나눈다.
  - 짧게 만들기 위해 서로 다른 지시를 한 문장에 새로 밀어 넣지 않는다.
- R3 [합의 Q1·Q3]: 기존 고유 지시와 의무 수준을 보존한다.
  - 각 스킬의 역할, 입력, 행동, 산출물, 종료 조건 및 조건부 예외를 바꾸지 않는다. 해당 요소가 원문에 있는 경우에 적용한다.
  - Evaluation → Checks → 판정, Define → Grill 등 역할이 다른 연결은 유지한다.

## Constraints

- C1 [합의 Q3]: 단계·승인 조건·담당·검증 방식 등 실행 정책을 변경하지 않는다.
- C2 [합의 Q4 수정·Q5]: 현재 언어·식별자·메타데이터와 파일 구성을 유지한다. 번역, 공통 제목·형식 통일, 템플릿·예시의 문서 간 이동을 하지 않는다.
- C3 [합의 Q2]: `AGENTS.md`, `docs/`, `skill-eval/`은 수정하지 않는다. `.goal/skill-readability/`의 작업 문서는 별도로 작성한다.
- C4 [합의 Q3·Q5]: 원래 의미를 확정할 수 없는 정책 문장은 이번 편집에서 그대로 둔다.
  - Execute 종료 상태, internal seam 테스트 범위, Handoff 재검증 범위에 새로운 정책 판단을 부여하지 않는다.
- C5 [합의]: 다른 작업의 기존 변경을 수정하거나 이번 커밋에 포함하지 않는다. 단계 이동과 단계별 커밋은 AGENTS.md를 따른다.
- C6 [합의 추가]: 실제 스킬 문서의 각 변경은 사용자의 개별 승인을 받은 뒤에만 적용한다.
  - 독립적인 국소 편집 하나를 승인 단위로 삼고, 식별자·파일·원문·수정안·이유를 먼저 제시한다.
  - 작은 편집에도 예외를 두지 않으며, 승인받지 않은 변경을 함께 적용하지 않는다.
  - 승인 후 수정안이 달라지면 바뀐 내용을 다시 제시하고 승인받는다.
  - 목표 합의나 단계 전환 요청을 구체적인 변경안의 승인으로 간주하지 않는다.
  - 이 제약은 대상 스킬 원문 편집에 적용한다. 합의 내용을 작업 문서에 기록하고 AGENTS.md에 따라 단계 완료 커밋을 만드는 것은 해당 단계의 작업으로 수행한다.

## Out of scope

- [합의 Q3] 단계·스킬 통합, 새 워크플로 정책, 승인 조건 변경.
- [합의 Q2] 외부 참고 자료와 평가 도구 구현 변경.
- [합의 Q5] 전체 재작성, 언어·공통 형식 통일, 새 참조 문서 도입, 정책 모호함 해소.
- [합의 Q6] 줄 수·글자 수의 감축률 목표와 새 에이전트 실행 실험.
- [Plan 사용자 결정] ticket 03·D1 이외의 수정. Plan과 ticket 03의 Execute는 요청받았으며, 독립 Verify 단계는 별도 요청 시 진행한다.

## Evaluation

아래 평가 방식은 Q6과 추가 승인 제약을 반영한다. 실제 결과는 Verify에서 기록한다.

| 대상 | Criteria: 성공 조건 | Method: 확인 방법 | Evidence: 판단 증거 |
|---|---|---|---|
| R1 | 평가 불필요: 사용자가 중복 제거 제안을 제외하고 반복 설명을 유지하기로 결정했다. | 해당 사용자 결정과 최종 변경 범위를 대조한다. | Plan 범위 조정 기록과 git diff. |
| R2 | 변경한 문단에서 정의·조건·행동을 분리해 찾을 수 있고 새로운 과밀 문장이 생기지 않는다. | 기준 버전과 최종 문단을 나란히 읽어 어떤 지시가 분리됐는지 확인한다. | 문단별 전후 발췌와 개선 이유. |
| R3 | 고유 지시·예외·의무 수준·역할별 연결이 빠지거나 새 정책으로 바뀌지 않는다. | 변경한 모든 구간의 지시를 원문과 대조한다. 기존 로컬 Markdown 파일 링크의 유효성도 확인한다. | 지시 보존 대조 결과와 링크 확인 결과. |
| C1 | 실행 정책이 보존된다. | 각 변경이 문장·구조 편집인지, 승인·담당·검증·종료 동작 변경인지 대조한다. | 변경 구간별 정책 보존 판단과 근거. |
| C2 | 기존 언어·식별자·메타데이터·파일 구성·템플릿 및 예시 위치가 유지된다. | diff와 변경 파일 목록을 확인한다. | diff, 파일 목록, frontmatter·위치 대조 결과. |
| C3 | 허용된 스킬 문서와 해당 작업 문서에만 변경이 있다. | 이번 작업의 커밋별 파일 목록을 확인한다. | 커밋별 변경 파일 목록. |
| C4 | 분석에서 지적한 미확정 정책 문장이 그대로다. | 해당 구간을 기준 버전과 직접 비교한다. | 세 정책 구간의 동일성 확인 결과. |
| C5 | 다른 작업의 변경이 보존되고 해당 작업만 단계별로 커밋된다. | 작업 전후 상태와 커밋 파일·메시지를 대조한다. | git status 및 커밋 기록. |
| C6 | 모든 스킬 변경이 구체적인 수정안의 사용자 승인 이후에 적용되고, 미승인 변경이 없다. | 최종 diff의 각 변경 구간을 변경안 식별자·사용자 응답·적용 기록에 대응시킨다. 수정안이 바뀐 경우 재승인도 확인한다. | 변경안별 원문·수정안·이유, 사용자 승인 기록, 적용 기록과 diff 대응표. |

- Markdown 지시문 편집이므로 코드의 테스트 seam을 정하는 분기는 적용하지 않는다.
- 정적 대조는 지시의 문면 보존을 확인한다. 에이전트 실행 정확성을 실험으로 입증했다고 해석하지 않는다.

## Round 기록

### Round 1 — 반영 완료

- Q1: 추천안 수용. 사람의 읽기·수정 편의가 주목표, 에이전트의 실행 정확성이 필수 조건이다.
- Q2: 추천안 수용. 10개 스킬과 부속 문서 4개를 검토하되 필요한 파일만 수정한다.
- Q3: 추천안 수용. 기존 규칙·의무 수준을 보존하는 편집에 한정한다.
- Q4: 추천안 수정. 사용자: “일단 지금 상태에서 최소한의 변경이면 좋을 것 같아. else accept”. 언어를 통일하지 않고 현재 상태를 최대한 유지한다.

### Round 2 — 반영 완료

- Q5: 추천안 수용. 같은 파일 안의 반복 문장 정리·긴 문장 분리로 한정하고, 기존 구성·템플릿·예시 위치와 미확정 정책 문장은 유지한다.
- Q6: 추천안 수용. 감축률이나 새 실행 실험 대신 전후 문장·고유 지시·변경 범위·링크의 대조를 평가 기준으로 삼는다.
- 추가 제약: 사용자: “accept all. 그리고 실제로 어떻게 변경할건지도 user의 허가를 일일이 받아야해”. C6과 평가 항목에 반영했다.

## Define 종료 확인

- 여섯 목표 구성 항목과 R1~R3·C1~C6의 평가 기준을 기록했다. 남은 미결정은 없다.
- 후속 Plan은 이 목표를 바탕으로 구체적인 변경안을 만들 수 있다. 각 변경안의 적용에는 C6에 따른 사용자 승인이 필요하다.
- Define 완료는 스킬 변경안의 승인이 아니다. 다음 단계는 사용자가 요청할 때 진행한다.

## Plan 사용자 범위 조정

- 사용자: “ticket3 정도만 진행하고 나머지 수정은 괜찮은 것 같아. 오히려 강조하는 느낌이라. ticket3만 진행해줘.”
- 확정: 기존 ticket 03·D1만 진행한다. 01·02·04·05와 P1·P2·CD1·CD2·T1·E1은 제외한다.
- D1은 앞서 원문·수정안·이유를 제시한 단일 변경이며, 수정안은 그대로다. 이 선택을 D1의 개별 승인과 ticket 03의 실행 요청으로 기록한다.
- R1의 중복 제거 요구는 제외하고 R2·R3와 C1~C6은 유지한다. 새 정책 결정은 추가하지 않는다.
