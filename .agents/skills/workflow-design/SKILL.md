# Design

`workflow-grill` 스킬을 로드해, goal.md와 관련 코드를 읽은 뒤 "어떻게 만들지"의 핵심 결정을 사용자와 함께 정하고,
결과를 `.goal/<goal>/design.md`에 기록한다.
`eli10` 스킬을 로드해, 질문마다 그 방식으로 배경과 용어를 먼저 설명한다.
이미 코드가 있으면 고칠 부분의 지금 구조를 먼저 그림으로 보이고, 바꿀 결정만 묻는다.

사용자와 함께 정하는 결정은 다섯 가지다.
- 아키텍처 패턴
- 핵심 계산에 닿는 함수·클래스의 이름, 맡는 일, 부르는 순서
- 핵심 계산이 주고받는 데이터 모양. 저장이 있으면 저장 모양까지
- 기술 스택. goal이나 기존 코드로 이미 정해진 것은 묻지 않는다
- seam. `codebase-design` 스킬을 로드해 그 용어로 정한다

질문마다 메인 세션이 만든 후보 2개 이상, 장단점, 잘못 고르면 생기는 일, 추천을 보인다.
그 밖의 결정은 AI가 정한다.

design.md에는 네 가지를 적는다.
- 지금 구조: 이미 코드가 있을 때만. 고칠 부분이 거치는 파일·함수를 ASCII 그림과 `파일:행`으로
- 결정: 함께 정한 결정마다 상황, 고른 것, 이유를 1~3문장으로. 이유는 "X를 얻는 대신 Y를 감수한다" 꼴로.
  버린 후보마다 왜 졌는지 한 줄. 이미 정해져 있던 것은 무엇으로 정해졌는지 한 줄
- 모양: 데이터 모양을 먼저 적고, 핵심 함수·클래스(이름, 맡는 일, 입력 → 출력)를 따라 데이터가 흐르는 ASCII 그림을 그린다.
  이상 입력을 어디서 거르는지 표시한다. 코드 파일은 만들지 않는다
- AI가 정한 것: 한 줄씩

Round마다 design.md를 갱신하고, 합의·미결정을 구분해 적는다.
함께 정할 결정마다 고른 안이나 "이미 정해짐"이 적히고 미결정이 없으면 끝. Define에서 불렀으면 Define으로 돌아간다.
